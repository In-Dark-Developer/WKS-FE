# PRD — 운꿰사 (WKS) 프론트엔드

- Status: Draft
- Last updated: 2026-09-11

## Problem

대학 축제에서 새로운 사람을 만나고 싶어도, 모르는 사람에게 먼저 말을 걸 계기가 없다. 기존 소개팅 앱은 진입 문턱(프로필·사진·과금)이 높고 축제라는 맥락과 무관하다.
"부처가 점지해준 나의 운명"이라는 사주 콘텐츠를 계기로 삼으면, 먼저 재미로 운세를 보고 친구에게 공유하다가 자연스럽게 소개팅 신청까지 이어질 수 있다.

## Goals

- G1. 생년월일만으로 30초 안에 사주 결과를 보고 점지 카드를 인스타에 공유할 수 있다.
- G2. 공유 링크로 들어온 친구가 자기 사주를 입력하면 궁합 점수(귀인/찰떡/벗/스침)가 서로의 페이지에 쌓인다.
- G3. 결과 화면 하단의 블러 처리된 소개팅 섹터가, 추가 정보 입력·동의를 거쳐 열린다.
- G4. 양측이 '운명의 실'을 주고받으면 연락처가 서로에게 공개된다.

## Target Users

- 축제에 참여하는 대학생(학교 이메일 보유): 재미있는 콘텐츠를 인스타에 공유하고 싶고, 부담 없는 만남의 계기를 원한다.
- 공유 링크로 유입된 친구: 처음에는 궁합 점수만 보러 오지만, 그 자리에서 자기 사주·소개팅 신청으로 전환될 수 있다.

## User Stories

- US-1. 축제 참가자로서 내 한 해의 운을 알기 위해 생년월일·시간·지역·성별·닉네임을 입력하고 싶다.
- US-2. 축제 참가자로서 자랑하기 위해 십이간지 캐릭터가 그려진 점지 카드를 인스타에 올리고 싶다.
- US-3. 공유 링크를 받은 친구로서 우리 사이의 인연을 확인하기 위해 내 사주를 입력하고 궁합 점수를 보고 싶다.
- US-4. 축제 참가자로서 내 인연들을 모아 보기 위해 친구 점수 목록(구슬 꿰매기)을 보고 싶다.
- US-5. 축제 참가자로서 소개팅 상대를 만나기 위해 추가 정보를 등록하고 블러를 해제하고 싶다.
- US-6. 축제 참가자로서 마음에 드는 상대에게 운명의 실을 보내고, 성립하면 연락처를 받고 싶다.

## Functional Requirements

| ID    | Requirement                                                                                                                | Priority | Related |
|-------|----------------------------------------------------------------------------------------------------------------------------|----------|---------|
| FR-1  | 시스템은 인트로(영상 + 문구 + 시작 버튼)를 사용자당 한 번 보여줘야 한다                                                     | Should   | US-1    |
| FR-2  | 시스템은 생년월일·태어난 시간·태어난 지역·성별·닉네임을 입력받아야 하며, 시간·지역은 '모름'을 허용해야 한다                | Must     | US-1    |
| FR-3  | 시스템은 사주 결과를 연애·재물·학업·축제 기간 아이템·운 다섯 영역으로 보여줘야 한다                                        | Must     | US-1    |
| FR-4  | 시스템은 결과 화면에서 공유 링크를 복사할 수 있게 해야 한다                                                                | Must     | US-2    |
| FR-5  | 시스템은 십이간지 캐릭터와 수치가 들어간 점지 카드를 이미지로 만들고 인스타 공유·저장할 수 있게 해야 한다                  | Must     | US-2    |
| FR-6  | 시스템은 공유 링크로 유입된 사용자가 자기 사주를 입력하면 두 사람의 궁합 점수를 보여줘야 한다                              | Must     | US-3    |
| FR-7  | 시스템은 궁합 점수를 25점 구간으로 귀인·찰떡·벗·스침 네 등급으로 표기해야 한다                                             | Must     | US-3    |
| FR-8  | 시스템은 내 페이지에 친구 점수 목록('구슬 꿰매기' 섹터)을 누적해 보여줘야 한다                                             | Must     | US-4    |
| FR-9  | 시스템은 결과 화면 하단의 소개팅 섹터를 블러로 가리고, 해제 조건(추가 정보 입력 + 동의)을 안내해야 한다                    | Must     | US-5    |
| FR-10 | 시스템은 추가 정보(학교 이메일 인증, 이름, 연락처, 사진, 학과, 나이, MBTI, 자기소개)를 입력받고 개인정보 동의를 받아야 한다 | Must     | US-5    |
| FR-11 | 시스템은 알림 신청을 완료한 사용자에게 1회 쿠폰 지급 사실을 보여줘야 한다                                                  | Should   | US-5    |
| FR-12 | 시스템은 소개팅 후보를 점지 카드 형태로 보여주되, 내가 입력한 항목에 대응하는 상대 정보만 노출해야 한다                    | Must     | US-6    |
| FR-13 | 시스템은 '운명의 실 보내기'와 상대의 '당기기'를 처리하고, 양측이 성립하면 서로의 연락처를 공개해야 한다                    | Must     | US-6    |
| FR-14 | 시스템은 공유 링크를 통한 유입을 기록해 내 페이지의 친구 점수와 연결해야 한다                                              | Must     | US-3    |

## Constraints

- 이 저장소는 프론트엔드 전용이다. 서버 API·DB·사주(만세력) 계산·LLM 문구 생성은 별도 백엔드 저장소가 소유한다.
- 디자인은 Figma를 따른다: https://www.figma.com/design/tzWb3S2guXz5zH2DMeX8Yt/ (node-id 12-4). 디자인 시스템·인트로·결과 화면·점지 카드·친구 점수·모달을 담당자가 나눠 만든다.
- 콘텐츠 톤은 '보살' 화법, 소재는 십이간지로 고정한다.
- 축제 기간이 실질 마감이다 — 일정은 미확정(TBD).

## Non-goals

- 앱 내 1:1 채팅 — MVP에서는 매칭 성립 시 연락처 교환으로 대신한다.
- 결제(상대 정보 열람 유료화) — 후속 Phase로 미룬다.
- 네이티브 앱, 운영자용 관리 도구, 다국어.

## Success Criteria

- G1: 인트로부터 점지 카드 공유까지 이탈 없이 완주 가능하고, 공유 버튼이 실제 인스타 스토리/저장으로 이어진다.
- G2: 공유 링크 유입자가 사주를 입력하면 양쪽 페이지의 친구 점수 목록에 등급과 함께 나타난다.
- G3: 추가 정보 입력과 동의를 마치면 블러가 사라지고 소개팅 섹터를 쓸 수 있다.
- G4: 양측 운명의 실이 성립한 경우에만 연락처가 노출된다 (미성립 시 노출 0건).
