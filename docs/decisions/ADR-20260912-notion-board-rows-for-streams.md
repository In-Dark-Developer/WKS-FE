# ADR-20260912: Task 아닌 스트림도 보드에 올린다 — 행은 동기화가 만든다

- Status: Accepted
- Date: 2026-09-12
- Deciders: @jjjung0921 (제안) / 리뷰어는 PR 승인자

## Context

ADR-20260912-notion-task-board-sync로 `ws/*` push·PR 이벤트가 Notion `✅ Task 보드`를 갱신하게 했다. 그때는 보드 행을 사람이 만들고 동기화는 갱신만 하기로 했다.

그 결과 spec·chore·plan·phase-close 스트림은 보드에 전혀 나타나지 않는다. 이들은 `Task: -/-`라 Phase+Task로 찾을 행이 없다. 실제로 지금까지 만든 스트림 다섯 중 넷이 여기 해당한다 — 보드만 보는 사람은 저장소에서 무슨 일이 벌어지는지의 절반을 못 본다.

## Problem

Task 아닌 스트림을 보드에 어떻게 올리는가. 행을 사람이 계속 만들게 할 것인가, 동기화가 만들게 할 것인가.

## Alternatives

1. **그대로 둔다** — 장점: 보드가 Phase 계획과 1:1로 단순하다. 단점: 팀 작업의 절반이 보드에 없다. 보드로 현황을 보는 사람에게는 저장소가 조용해 보인다.
2. **사람이 행을 먼저 만든다** — 장점: 이전 ADR의 "행은 사람이 만든다"를 유지한다. 단점: 스트림을 열 때마다 Notion을 열어 행을 만들어야 한다. 안 만들면 조용히 누락되고, 그 누락을 아무도 못 본다.
3. **동기화가 행을 만든다(선택)** — 장점: 스트림을 열면 보드에 나타난다. 사람이 할 일이 없다. 단점: 보드 행 목록의 일부를 자동화가 소유하게 된다. 손으로 지운 행은 다음 push에 되살아난다.

## Decision

3번을 택한다. ADR-20260912-notion-task-board-sync의 "행은 사람이 만든다"를 **Task 행에 한정**하는 것으로 좁힌다.

- 보드에 `Stream`(text) 속성을 추가했다. 모든 동기화가 스트림 id를 여기 쓴다.
- **Task 스트림**(`01/T3`): 전과 같다. Phase 번호 + Task로 사람이 만든 행을 찾고, 없으면 건너뛴다. Phase 계획이 행 목록의 주인이다.
- **그 밖의 스트림**(spec·chore·plan·phase-close): `Stream` 열로 찾고, 없으면 만든다. 만들 때 제목은 CURRENT의 `## Current Task` 첫 줄, `Touches`도 함께 쓴다. `Phase`·`Task` 열은 비운다.
- 상태 매핑과 단방향 원칙은 그대로다. 보드를 고쳐도 저장소는 바뀌지 않는다.

## Consequences

- 스트림을 열고 push하면 보드에 행이 생긴다. 열지 않은 작업은 여전히 보드에 없다 — 보드가 아니라 스트림이 단위다.
- 손으로 지운 자동 생성 행은 그 스트림이 다시 push되면 되살아난다. 병합돼 끝난 스트림은 더 push되지 않으므로 지우면 지워진 채로 남는다.
- `Stream` 속성 이름을 바꾸면 동기화가 실패한다(CI가 빨개진다).
- Task 행에는 `Stream`만 추가로 쓴다. 제목·Phase·Task·Touches는 사람 것이다.
