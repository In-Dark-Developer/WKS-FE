# ADR-20260915: 공유 링크 미리보기는 모든 경로에 같은 메타를 쓴다

- Status: Accepted
- Date: 2026-09-15
- Deciders: @jjjung0921 (Phase 08 Lead, 제안) / 리뷰어는 PR 승인자

## Context

공유 링크(`https://threadoffate.site/s/{shareId}`)가 유입의 전부라(US-2·US-3) 카카오톡·인스타·메신저에 붙였을 때 제목·설명·썸네일이 보여야 한다 (NFR-3, SC-6).

앱은 Vite SPA 이고 Netlify 가 모든 경로에 같은 `index.html` 을 준다(`netlify.toml`, ADR-20260914-netlify-personal-fork). 미리보기 크롤러는 JS 를 실행하지 않으므로 크롤러가 읽는 것은 `index.html` 의 `<head>` 뿐이다. 08/T4 가 거기에 서비스 공통 OG·Twitter 메타를 넣었다(commit d32d0e7).

링크마다 다르게 보여 줄 수 있는 재료는 적다. `GET /shares/{shareId}` 는 주인의 닉네임·운명·등급을 내려주지만, 방문자에게 주인의 사주 요약(운명 제목·등급)은 보여주지 않는다(FR-15). 남는 것은 닉네임인데, 그것도 숨길지가 미정이다(PRD Q12). 제약은 MVP 마감 2026-09-17 이다.

## Problem

`shareId` 별로 미리보기 제목·설명·이미지를 바꾸는 동적 미리보기를 MVP 에 넣을 것인가, 넣는다면 어디서 HTML 을 만들 것인가.

## Alternatives

1. **모든 경로에 같은 메타** (현재) — 장점: 추가 런타임·호출이 없고 이미 병합 가능하다. 주인 정보가 미리보기로 새지 않는다(FR-15·Q12 결과와 무관하게 안전). 단점: 모든 링크가 같은 문구라 "누가 보냈는지"가 미리보기에 안 보인다.
2. **Netlify Edge Functions** — `/s/*` 요청에서 `GET /shares/{shareId}` 를 불러 `index.html` 의 메타를 닉네임으로 바꿔 돌려준다. 장점: 프론트 저장소 안에서 끝나고 공유 URL 이 그대로다. 단점: Deno 런타임 코드가 새로 들어오고(AGENTS.md Rule 13 — 새 런타임은 ADR), 크롤러·사용자 요청마다 백엔드 호출이 붙어 `/s/*` 첫 응답이 백엔드 지연에 묶인다. 무료 플랜 호출 한도와 private fork 빌드 제약 아래 동작을 확인해야 한다. 보여줄 것이 닉네임뿐인데 그것도 Q12 가 숨기면 얻는 것이 없다.
3. **백엔드 렌더** — 백엔드가 `shareId` 별 메타 HTML(과 OG 이미지)을 만든다. 장점: 데이터 곁에서 만들고, 인연카드 이미지와 재료를 공유할 수 있다. 단점: 공유 URL 은 `threadoffate.site`(Netlify) 인데 백엔드는 `api.threadoffate.site` 라 크롤러 요청을 백엔드로 보내는 프록시가 필요하다. 계약에 그런 엔드포인트가 없고 백엔드는 다른 팀 저장소다. 마감 전 합의·구현이 불가능하다.

## Decision

1 을 택한다. MVP 에서는 모든 경로가 `index.html` 의 공통 OG·Twitter 메타를 쓰고, `shareId` 별 동적 미리보기는 하지 않는다.

다시 여는 조건: Q12 가 "닉네임을 보여준다"로 정해지고, 기획이 미리보기에 닉네임을 원할 때. 그때는 2(Edge Functions)를 먼저 검토하는 새 ADR 을 쓴다 — 3 은 공유 도메인 프록시와 백엔드 계약 변경이 함께 필요하다.

## Rationale

- 동적으로 바꿀 재료가 닉네임 하나이고, 그 노출 여부(Q12)가 정해지지 않았다. 정해지지 않은 개인정보 노출을 위해 런타임을 들이지 않는다.
- SC-6 의 기준은 "제목·설명·썸네일이 보인다"이지 링크마다 다르다가 아니다. 공통 메타로 충족한다.
- 마감(2026-09-17)과 실기기 검증 기간(09-18 ~ 09-28) 안에 새 런타임·백엔드 협의를 끼우면 T6 출시 점검이 밀린다.

## Consequences

- 긍정: 배포 구성이 그대로(정적 `index.html` + SPA 폴백)다. 미리보기가 백엔드 장애와 무관하게 뜬다. 주인 정보가 채팅방 미리보기로 새지 않는다.
- 부정 / 감수한 것: 받은 사람이 미리보기만으로는 누가 보낸 링크인지 모른다 — 공유하는 사람이 메신저에 직접 말을 붙이는 것에 기댄다. 카카오는 URL 별로 미리보기를 캐시하므로 메타를 바꾸면 카카오 공유 디버거로 캐시를 지워야 한다.
- 후속 작업: 썸네일(`og:image`, 1200×630)은 디자인 전달 후 `public/og/` 에 추가(08/T4). Q12 결정 시 이 ADR 의 재검토 조건을 확인한다.
