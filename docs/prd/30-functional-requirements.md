## Functional Requirements

디자인(「UI 최종 - 개발용」)과 이 문서가 어긋나면 **디자인이 우선한다**(2026-09-12 결정). 아래 FR은 그 원칙으로 디자인에 맞춰 고친 것이다. 단, 2026-09-13 기획 피드백으로 확정한 항목(FR-3 등급 체계·행운의 장소, FR-5 등급 표기, FR-9·FR-12 열람권과 오픈일, FR-15 사주 요약 제외)은 디자인보다 우선하며, 어긋나는 디자인(인연카드의 0–100 바)은 디자인을 고친다.

| ID    | Requirement                                                                                                                | Priority | Related |
|-------|----------------------------------------------------------------------------------------------------------------------------|----------|---------|
| FR-1  | 시스템은 `/` 첫 방문에 8초 인트로 영상을 보여줘야 한다: 처음 2초는 건너뛰기 칸에 숫자 카운트다운(2 → 1)이 보이고 2초부터 건너뛰기 버튼이 나타나며, 영상이 끝나거나 건너뛰면 사주 입력으로 넘어가며 이후 방문에는 보이지 않는다. 다른 경로로 들어오면 보이지 않는다. 공유 링크 입력(SCR-06)으로 처음 들어온 방문자에게도 보인다 | Could    | US-1    |
| FR-2  | 시스템은 사주 입력을 받아야 한다: 성별(남자/여자) · 달력 기준(양력/음력) · 생년월일(숫자 8자리 YYYYMMDD) · 음력이면 윤달 여부 · 태어난 시간(12시진 선택 또는 '몰라요' — 자시는 00:00–01:30·23:30–24:00 두 칸이라 13칸, 값은 칸의 가운데 시각) · 닉네임(1–8자). 태어난 지역은 받지 않는다(사주에 영향이 작아 2026-09-13 제외 — 백엔드 계약에서도 빠졌다). 필드별 검증 실패 문구를 띄우고, 연결 실패 시 입력값을 유지한다 | Must | US-1 |
| FR-3  | 시스템은 사주 결과를 운명 카드로 보여줘야 한다: 십이간지 보살 캐릭터, 운명 제목·설명(운명 카드 문구 영역 — 설명은 공백 포함 140자 이내(Figma 658:5130 주석), 제목은 한 줄에 들도록 글자 크기를 줄이고, 둘 다 말줄임 없이 전문을 보인다. 2026-09-15), 연애운·결혼운·자녀운 3영역(문자 등급 6단계 SS·S·A+·A·B+·B + 보살 말투 문구), 음양오행(사주 원국의 목·화·토·금·수 개수를 오행마다 8칸 막대로 — Figma 982:3446, 2026-09-17), 행운의 장소(동국대 캠퍼스 안)·행운의 아이템. 결과 대기 중 로딩 상태, 실패 시 에러 상태를 갖는다 | Must | US-1 |
| FR-4  | 시스템은 '친구에게 공유' 버튼으로 공유 링크(`/s/:shareId`)를 공유할 수 있게 해야 한다. 결과 화면에서는 친구 궁합 순위가 비어 있으면 안내 아래(Figma 796:3828), 있으면 목록 아래(Figma 796:3885, 2026-09-17)에 둔다. 궁합 지도에서도 공유할 수 있다. 공유 방식(OS 공유 시트 · 링크 복사 · 완료 안내)은 디자인·기획서에 없어 미정 | Must | US-2 |
| FR-5  | 시스템은 결과 화면(SCR-04)의 운명 카드(앞면: 캐릭터 + 연애운·결혼운·자녀운 문자 등급 SS~B 6단계 — 수치가 아니라 등급, 뒷면: "운명도 꿰어야 사랑이다")에 '카드 뒤집기' 버튼을 두어 앞뒤를 전환하고(결과 화면에 들어오면 뒷면부터 보인다), 카드 바로 아래 '카드 저장하기'(Figma 796:3862, 2026-09-17 '인스타 스토리 공유하기'에서 바뀜)로 카드 앞면을 이미지로 만들어 Web Share(파일)로 넘겨 기기에 저장하게 해야 한다. 별도 인연카드 화면은 없다(2026-09-15) | Must | US-2 |
| FR-6  | 시스템은 공유 링크로 들어온 사용자의 궁합을 만들어 링크 주인의 궁합 지도로 보내야 한다: SCR-06 에서 사주를 입력해 '운명 지도 확인하기'를 누르면 결과 대기(SCR-03)를 보여주며 결과(`POST /results`)와 궁합(`POST /shares/{shareId}/compatibility`)을 차례로 만들고 SCR-13 으로 간다. 이 브라우저에 내 결과가 이미 있으면 링크로 들어올 때 입력 없이 궁합을 만들고 SCR-13 으로 간다 — 단 이 탭에서 이미 궁합을 만든 뒤 뒤로가기로 돌아온 입력 화면은 폼을 보여주고, 다시 제출하면 새 결과를 만든다(주인 지도에 한 번 더 들어간다). 자기 링크(`SELF_COMPATIBILITY`)면 궁합 없이 자기 결과(SCR-04)로 가고, 궁합 생성이 실패하면 오류를 안내하며 다시 시도는 입력 없이 궁합만 다시 부른다. SCR-13 에는 뒤로가기가 없다. '내 사주 내용도 확인하기'는 자기 결과(SCR-04)로 가고, 그렇게 들어온 SCR-04 에만 맨 위 '뒤로가기'가 있어 SCR-13 으로 돌아간다 — 지도와 내 사주를 오갈 수 있다(2026-09-15 Figma 개정, 720:3668·720:3587) | Must | US-3 |
| FR-7  | 시스템은 궁합 점수를 네 등급으로 표기해야 한다 — 귀인 90 이상 · 찰떡 75–89 · 벗 61–74 · 스침 60 이하. 등급 값은 백엔드가 주며 화면이 계산하지 않는다 | Must | US-3 |
| FR-8  | 시스템은 궁합 지도 화면에 친구를 구슬(등급별 색)로 그리고, 등급별 인원 수와 친구 궁합 순위 목록을 누적해 보여줘야 한다. 구슬은 자기 등급 색 궤도 위에 놓인다 — 달에서 가까운 줄부터 귀인·찰떡·벗·스침(2026-09-15 소유자 결정). 결과 화면 하단에는 순위 요약을 두고, 인연이 없을 때는 "아직 인연이 없어요" + 공유 CTA를 보여준다. 결과 화면 순위 요약 제목 줄 오른쪽의 '지도 보기 >'는 궁합 지도(SCR-08 `/me/map`)로 이동한다(Figma 798:3138). 순위는 점수 높은 순이다. 지도는 움직인다(2026-09-15 소유자 결정): 궤도 선은 늘 제자리에서 30초에 한 바퀴 돌고, 친구 3명 이상이면 구슬이 자기 궤도의 지도 패널 안 구간(패널 가장자리까지, 제목 뒤로 지나갈 수 있다)을 10초 동안 흐른 뒤 10초 동안 숨었다가 다시 나온다 — 구간 양 끝 10° 에서 서서히 옅어져 바깥 궤도일수록 길게 옅어진다 — 같은 궤도 구슬은 친구마다 고정된 랜덤 자리(닉네임으로 정해 새로고침해도 같다)에서 서로 44px 이상 떨어져 출발해 겹치지 않고, 한 궤도에 그 간격이 들어가지 않을 만큼 많으면 보이는 10초는 그대로 두고 숨는 시간을 늘린다. 구슬 수 제한은 없고(2026-09-15), 닉네임은 똑바로 선다. 기기의 '동작 줄이기' 설정이면 멈춘다 | Must | US-4 |
| FR-9  | 시스템은 결과 화면 맨 아래에 소개팅 사전신청 섹션(873:4155 — 오픈일·서비스명과 '사전 신청하고 알림 받기')을 두고, 누르면 사전신청 모달(SCR-09)을 열어야 한다. 사전신청(작성·동의) 완료가 곧 상대 정보 열람권이다. 사전신청 전에는 상대 정보가 화면·응답 어디에도 없어야 한다 | Must | US-5 |
| FR-10 | 시스템은 사전신청 모달에서 이름 · 이메일 · 연락처 · 학과 · MBTI(16유형 선택) · 자기소개 · 성별 · 선호 성별을 입력받아야 하며, 기본/오류/로딩/실패/완료 상태를 갖는다. 연락처는 전화번호 또는 인스타그램 아이디 **택1**이다(디자인의 세그먼트 그대로 — 백엔드가 `contactMethod` 하나와 값 하나를 저장한다). 성별·선호 성별은 `POST /signups` 필수값인데 디자인에 없어 폼에 세그먼트 두 줄로 넣는다(2026-09-16 결정). 사진은 받지 않는다(2026-09-17 결정 — 디자인의 '사진 추가' 칸을 뺀다) | Must | US-5 |
| FR-11 | (MVP 제외) 알림 신청 완료 시 1회 쿠폰 지급 사실을 보여준다 — 디자인 없음, Non-goals 참고                                     | Could    | US-5    |
| FR-12 | 시스템은 백엔드가 궁합 점수를 바탕으로 제공하는 소개팅 후보 목록을 점지 카드 형태로 보여주되, 내가 입력한 항목에 대응하는 상대 정보만 노출해야 한다. 소개팅 후보 화면은 축제 당일(2026-09-29)부터 열리며, 그 전 접근 시 안내 상태를 보여준다(오픈 판정 주체는 Q13). 화면 디자인은 미정(SCR-10) | Must | US-6 |
| FR-13 | 시스템은 '운명의 실 보내기'와 상대의 '당기기'를 처리하고, 양측이 성립하면 서로의 전화번호와 (등록한 경우) 인스타그램 아이디를 공개해야 한다. 성립 후 대화는 앱 밖에서 한다 — 앱 내 채팅 없음(2026-09-13 확정, Non-goals). 화면 디자인과 API 형태는 미정(SCR-11) | Must | US-6 |
| FR-14 | 시스템은 공유 링크로 들어온 사람의 궁합을 링크 주인의 궁합 지도·순위에 누적해야 한다 — 궁합 지도(SCR-08) 맨 아래 '친구에게 공유하고 궁합 지도 넓히기'가 `/s/:shareId` 를 공유한다(Figma 558:2571) | Must | US-3 |
| FR-15 | 시스템은 SCR-06 부제에 "아래 정보를 입력하고 나와 <링크 주인 닉네임> 님의 귀인 궁합을 관계로 확인해보아요."(Figma 720:3653 문구 그대로)를 보이고, SCR-13 에 링크 주인의 궁합 지도(주인 닉네임 제목, 부제 "닉네임님과의 궁합 지도예요.", 구슬·등급별 인원·친구 궁합 순위)를 보여줘야 한다(Figma 720:3668). 두 화면 모두 주인의 사주 요약(운명 제목·설명·등급·십이간지·행운)은 제공하지 않는다. 주인에게 친구가 없으면 순위 빈 상태는 SCR-08 과 같다. 없는 링크는 오류 상태를 보여준다 | Must | US-3 |
| FR-16 | 시스템은 Web Share를 지원하지 않는 브라우저에서 인연카드를 이미지로 저장하는 폴백을 제공해야 한다                         | Must     | US-2    |
| FR-17 | 시스템은 사전신청 모달에서 수집 항목·이용 목적·보관 기간을 고지하고 동의를 받아야 하며, 동의 없이는 추가 정보를 전송하지 않아야 한다. 동의 UI는 디자인시스템 PreRegistrationForm의 OptionalConsent 슬롯을 켜서 쓴다. 이용약관 전문(695:2753 「이용약관 / 개인정보 및 사주 결과 안내」)은 사주 입력(SCR-02)과 사전신청(SCR-09) 양쪽에서 바텀시트로 연다 — 사전신청 시트는 읽을 거리이고 동의는 체크박스가 받는다(2026-09-16 결정). 사주 입력(SCR-02)의 시트에는 맨 끝에 [동의] 절(''점지 확인'을 누르시면 … 동의한 것으로 간주됩니다')을 둔다(2026-09-17 소유자 결정) — 사전신청 시트에는 두지 않는다 | Must | US-5 |
| FR-18 | 시스템은 이 브라우저가 만든 사주 결과가 아닌 결과 주소(`/reading/:id`)에 접근하거나, 이 브라우저가 만든 사주 결과가 없는 상태에서 궁합 지도·소개팅 화면에 접근하면 사주 입력(SCR-02)으로 안내해야 한다. 공유 링크 입력(SCR-06)은 안내 대상이 아니고, 결과 없이 친구의 궁합 지도(SCR-13)에 오면 SCR-06 으로 안내한다 | Should   | US-4    |
