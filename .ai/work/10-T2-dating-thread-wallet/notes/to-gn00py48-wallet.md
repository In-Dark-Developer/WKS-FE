## 1. 잔액의 출처가 `GET /wallet` 하나로 바뀝니다

백엔드가 실 원장을 구현했습니다(WKS-BE dev `adf54ab`, api-spec §12).

- `GET /wallet` → `{ balance, canCheckInToday }` — **화면에 보이는 잔액은 이제 여기서만 읽습니다**
- `POST /wallet/check-in` → 출석 +5 (하루 1회, 이미 받았으면 오류가 아니라 `checkedIn: false`)
- `GET /me` 의 `threadBalance` 는 **진입 게이트용 요약**으로 남깁니다 — 카드 화면에서는 쓰지 않습니다

카드 loader(`recommendationsLoader.ts`)가 `getMe()` 대신 `getWallet()` 을 부르도록 바꿨습니다. 해금 뒤 `revalidate()` 가 도는 흐름은 그대로라, 해금 응답의 `balance` 와 화면 잔액이 어긋나지 않습니다.

## 2. 목 잔액 규칙을 백엔드와 맞췄습니다

11/T1 의 목은 "프로필 등록하면 10" 이었는데, 백엔드는 **카카오 최초 로그인 시 10**(계정당 1회)입니다. 목 계정을 원장 모양으로 바꿨습니다 — `threadEarned`(가입 10 + 출석 5×n) − `threadSpent`(해금). `spendMockThread` 시그니처는 그대로라 `unlocks.ts` 는 수정하지 않았습니다.

## 3. 확인 부탁 — 궁합 까닭 해금이 503 일 때

백엔드 §10.5 에 이렇게 적혀 있습니다.

> `REASON` 은 첫 해금 성공 시점에 LLM 으로 생성해 캐싱한다 — 생성이 실패하면 `LLM_UNAVAILABLE` 503 이지만 **차감은 이미 끝난 뒤**이므로 다시 호출하면 차감 없이 생성만 재시도한다.

지금 `unlockFlow` 는 503 을 일반 실패로 보고 멈추고, 화면에는 "열지 못했어요" 안내만 뜹니다. 사용자는 **실만 날렸다고 오해**할 수 있습니다. 실제로는 다시 누르면 추가 차감 없이 열립니다.

제안: 503 만 따로 보고 "이미 실은 사용됐어요. 다시 누르면 추가 차감 없이 열려요" 같은 문구를 쓰는 건 어떨까요. 해금 화면은 11/T1 소유라 제가 고치지 않았습니다.

## 4. 그대로 둔 것

- `value: null` 인 열린 항목을 비용 0 잠금으로 돌리는 처리 — 좋은 방식이라 유지했습니다
- 출석 체크 버튼은 만들지 않았습니다 — 디자인은 있으나 퍼블리싱 Task 몫이라 API(`checkInWallet`)만 두었습니다
